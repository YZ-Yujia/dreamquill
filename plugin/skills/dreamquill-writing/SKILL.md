# Dreamquill 五阶段创作流程

你在辅助作者创作一部小说。书的全部产物（正文/三级大纲/世界观/角色/记忆/风格）都在书目录文件中，经 Dreamquill 工具读写。**产物写操作直接落盘**——因此两条硬确认纪律（见下）之外的动作可直接执行，但要在对话中向作者汇报每次写入。

## 启动流程（每次会话开始时）

1. 项目根 `AGENTS.md` 是**持久创作上下文**——按其中「创作进度快照」恢复现场；文件缺失或无快照段时，按「新开/压缩会话后的恢复步骤＋创作进度快照」结构补建/补段（既有内容不动）。
2. `getCurrentBook` 确认书已就绪；返回 null（项目根尚未初始化为书）时与作者确认书名后 `initBook`——项目根即书目录，不在项目内另建书目录。
3. `getBookStage` 取当前阶段；未设定（null）时按「创意构思」起步并与作者确认。
4. 按下方对应阶段的指引开工。跨会话续写时，`getWritingContext` 可快速恢复现场。

## 五阶段指引

阶段推进方向：构思 → 全文大纲 → 分卷大纲 → 章节大纲 → 正文。

### 阶段一：创意构思（ideation）

- 组装：会话开始 `getStaticContext` 一次（风格＋角色状态卡＋世界）；对话中新概念按需 `searchWorld`/`searchMemories` 查证（scanText 触发机制在动态层，构思期用全量 `getWritingContext({stage:'ideation'})` 恢复现场亦可）。
- 工作：与作者对话打磨世界观/角色/故事概念；新设定用 `upsertWorldEntry`/`upsertCharacter` 落盘（建议作者过目内容后写入）。
- 完成标准：世界观与主要角色成形，作者认可进入大纲。

### 阶段二：全文大纲（full-outline）

- 组装：`getStaticContext` 一次；
- 工作：基于既有设定起草全书大纲——`大纲/全文大纲.md`；起草中引入的新设定随手入库（见通用纪律「设定随写随入库」），不堆进大纲文件。
- 完成标准：主线/卷划分/关键转折齐备，作者认可。

### 阶段三：分卷大纲（volume-outline）

- 组装：`getStaticContext` 一次；
- 工作：逐卷细化（分卷大纲在 `大纲/分卷大纲/` 下，路径经 `readManuscript` 定位，结构模板见空态返回）；开始新一卷先 `createVolume`（卷名与作者商定）。
- 完成标准：各卷主线/支线/节奏齐备。

### 阶段四：章节大纲（chapter-outline）

- 组装：`getStaticContext` 一次；邻近章细纲可经 `readManuscript({scope:'chapter-outline'})` 查阅参考（可传全书序号 order）。
- 工作：为本卷逐章写细纲——新章先 `createChapter`（**默认只落细纲骨架**；卷定位 volumeId/卷序二选一），对骨架填小节内容（`## 小节` 结构，路径＝返回的 outlinePath）。
- 完成标准：当前卷全部章纲就绪。

### 阶段五：正文（draft）

- 组装（分层，防上下文膨胀）：会话开始 `getStaticContext` 一次；**每次写作前** `getChapterContext({chapterId, scanText})`——轻量动态层（细纲＋触发记忆）。scanText＝近期对话要点。**连续续写**（本章是本会话刚写）不带 tailChars——对话历史即前文；**跳章续写**（本章非本会话所写）带 `tailChars: 800`，中段细节需要时直接原生 Read 取真值（路径经 `readManuscript` `metaOnly` 定位）。
- 工作：按章纲逐章写作——正文路径来自 `createChapter` 返回或 `readManuscript` metaOnly；**正文文件未建时直接原生 Write 该路径**。字数与风格遵守 `getStyleRules`；写后可经 `readManuscript`（`metaOnly`）回查字数。章节序号全书连续（跨卷不重置），由工具自动维护。先写正文后补细纲的章，建议 `createChapter` 传 order 补建（自动填模板骨架，不覆盖既有），或原生 Write 细纲路径（无模板）。
- **写后三级审阅（自动触发，主会话直出）**：每次整章 Write 后，你在主会话直接按三轮方法论审本章——正文刚写完就在上下文里，无需重读文件；细纲与风格规范按需查 `readManuscript({scope:'chapter-outline'})`／`getStyleRules`——
  1. **轮一·细纲符合性**：对照章纲逐节查情节点落实（缺漏逐条列）、细纲外重大内容（跑题，小节内合理展开不算）、推进度（未推进/过度都报）；
  2. **轮二·逐句节奏**：以读者视角逐句过——拖沓（信息密度低、同义反复）、断裂（指代丢失、逻辑跳跃、场景切换无过渡）、句长排布单调、紧张段被拖长、与风格规范冲突的表达习惯；
  3. **轮三·逐字用词与句式**：调 `lintSentencePatterns`（候选≠违例，逐条按许可条件裁决）＋全文语义扫六类句式＋错别字/词义误用/时代用语；
  4. 报告有违例 → 按报告**一次改写**，只改报告点名的位置，不动其余；**改写后不触发复审**（信任单次改写，余留问题交作者把关）；
  5. 交付时附三轮报告摘要并明示「已按审阅报告改写，请过目」；「待作者裁决」项原样呈报，不擅自改。报告干净 → 直接交付；作者要求跳过审阅时遵从但注明「未审阅」。
  - **裁决纪律（召回优先，宁滥勿缺）**：存疑即报进「待作者裁决」，确定的违例照常判——只报确定项而漏掉存疑项才是失职；每条问题带引文＋理由＋改法方向（不代写全文）。
  - **六类 AI 凑句式许可条件（轮三）**：对比重构＝被否定的 A 须是真实备选（有人真信/真实预期）；排比三联＝三项各自独立成立、值得各占一位；设问＝读者此刻真可能问；金句收尾＝结论须由前文挣得（earned）；比喻＝源域与目标域有真实结构映射；否定强调＝排除的是真实存在的混淆项。
- 完成后：向作者汇报；作者处理裁决项后本章无遗留问题，默认执行收口。
- **定稿≠冻结**：定稿只标记「作者认可的版本基线」，不锁内容——作者要求修改定稿章时直接改，不重新三级审阅；章状态单向（无回退草稿路径）。
- **章内容落定即收口**：首次定稿（作者裁决完结后）、已定稿章修改完毕，各执行一次 `/定稿收口`——`draftFinalizePack` 标记章 final 并返回材料包，一致性问题＋记忆提炼＋状态盘点一次裁决（规则见通用纪律「记忆与引用维护」）；再调＝增量对账（材料含既有记忆清单，与既有条目比对给 merge/disable 建议，不重复入库）。收口后更新 AGENTS.md 快照。

## 硬确认纪律（仅两处，skill 层约定）

1. **切阶段**：`setBookStage` 前必须向作者说明目标阶段与理由并获确认（阶段决定后续组装场景）。
2. **记忆入库**：`writeMemoryEntry` 前必须完整呈现条目内容（类型/标题/内容/触发词/冲突建议）并获作者确认（记忆库污染会长期影响创作上下文）。

其余写操作（章/大纲/世界观/角色）直接执行＋事后汇报。

## 通用纪律

- **持久上下文维护**：阶段切换后、章定稿后、重大设定变更后、长会话收尾时，把「当前阶段／进度要点／待办与约定」**整段重写**进项目根 `AGENTS.md` 的创作进度快照段——合并已消化项、删过期项，只保留三要素的现状视图（全段 ≤20 行），固定指引段勿动；重要历史决策沉淀记忆库（`writeMemoryEntry`），不堆快照——新开与压缩会话的现场恢复全靠它。
- **分层取用（防上下文膨胀）**：`getWritingContext` 全量组装**只用于现场恢复**（新会话/上下文压缩后/切阶段）——同会话内勿反复调用；日常＝`getStaticContext` 会话级一次＋`getChapterContext` 每次写作前；工作物（大纲/细纲/正文）直接用原生工具读写。各工具「预算报告」中被截断的块/未装下的记忆要向作者转述。
- **按需查证**：写作与对话中遇到先前概念（地名/人物/伏笔）时主动 `searchWorld`/`searchMemories` 查证，不凭印象；情节引入新元素且相关设定未在本会话出现过的，先查再写。
- **事实查证**：回答「某伏笔在哪章埋的」类问题用 `searchMemories`/`searchWorld`，不要凭印象作答；伏笔回收闭环用 `resolveForeshadow`。
- **记忆与引用维护**（设定＝固有属性，记忆＝剧情状态）：设定/角色只写**不随剧情变的定义性内容**（物品的来历、地点的地理、人设与关系）——剧情导致的**当前状态**（物品易手/损毁、角色伤势/位置/生死、事件进展、伏笔的埋设/推进/回收）一律写**记忆条目**（type=状态变化/伏笔/剧情摘要，fromChapter＝生效起始章），不回改设定；角色状态卡的「当前状态」由「状态变化」类记忆自动组装。两条硬规则：①**状态变化类 keywords 必含主体名**（角色/物品名）——状态卡按主体名归属，缺名不挂卡、触发也不命中；②**记忆正文与大纲产物主动用 `[[条目名]]` 引用世界观条目**——上下文只组装被引用的设定，[[引用]] 链会逐层带出关联条目，不写引用＝写作时设定不进上下文。状态盘点经 `/定稿收口` 一并裁决。
- **设定随写随入库**：不只构思阶段——**任何阶段**（大纲/细纲/正文/收口/对话）新确定的设定性内容（新地点/势力/物品/规则/历史，新出场且有戏份的角色）都要随手 `upsertWorldEntry`/`upsertCharacter` 落进对应类型条目（先 `listWorldTypes` 复用既有类型），剧情状态变化按「记忆与引用维护」走记忆条目。**禁止把新设定写进全文大纲/分卷大纲/AGENTS.md 代替条目**——大纲只承载剧情结构（事件/节奏/转折），AGENTS 快照只承载进度三要素；设定不入库＝不进后续上下文（组装只认条目与 [[引用]]），拖到收口才发现就晚了。条目内容建议作者过目后写入（同构思阶段惯例）。
- **产物定位**：路径经 `readManuscript`（`metaOnly`）或各清单获取；内容读写直接走原生工具。书根 `进度看板.md` 为插件自动生成的**作者视图**（统计/状态聚合/组装快照）——agent 勿读取、勿编辑，需要进度与状态真值时走插件工具。
- **原生文件工具分工**：**内容读写全部走 原生工具**（Read/Edit/Write）——章正文（path）与章纲（outlinePath）与分卷大纲见 `readManuscript` metaOnly；全文大纲＝`大纲/全文大纲.md`；条目正文块＝世界观/角色/风格示例文件 frontmatter 头以下的正文（path 见各清单与检索返回）。唯一红线＝**不改坏结构**：frontmatter 头、文件命名与目录位置不动（条目头部字段如类型/标签/分组的变更走 upsert 工具）；记忆条目不开放（走 `writeMemoryEntry`——头部字段常随内容联动改）。**结构操作一律走插件工具**：建/删/改名/移动/定稿/卷管理/关系对/类型注册背后有索引联动、全书重编号、两域成对、[[引用]] 改写，原生文件操作会绕过它们造成库损坏；`.dreamquill/`、`关系/`、各域 `索引.md` 等应用结构文件禁碰。
- **新条目命名**：世界观/角色按名称 upsert（不产生重复）；章按 `createChapter` 建（文件名自动编号）。新建世界观/记忆条目的类型未注册时工具会自动注册——但先 `listWorldTypes`/`listMemoryTypes` 查看既有类型，优先复用，避免造出同义重复类型。
- **删除类操作**：删章/删卷（force）/删条目/删角色/删关系对不可恢复，按工具描述的警示先向作者确认再执行；角色关系对经 `addCharacterRelation`/`updateCharacterRelation`/`removeCharacterRelation` 维护。
